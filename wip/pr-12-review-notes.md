# PR #12 review notes — deferred items

Recorded 2026-07-21 while triaging the agent review comments on the `Release v0.6.0` PR (https://github.com/Pipelex/pipelex-mcp/pull/12). One confirmed item was deferred rather than fixed on the release branch.

## Paywall (402) summaries use the connectivity headline

- **Reporter:** greptile-apps (P2), on `src/capabilities/shared.ts` (the 402 arm of `classifyApiResponseError`). Thread: https://github.com/Pipelex/pipelex-mcp/pull/12 (left unresolved).
- **Issue:** a 402 classifies as `config` (deliberate, documented — TODOS decision 4, SPEC.md classification), and every `config`→summary mapping emits the connectivity headline: "… could not start: the Pipelex API is unreachable or misconfigured." (five mappings: `validate.ts` `summaryForError`, `inputs.ts` `summaryForError`, and `run.ts`'s three `*_ERROR_SUMMARIES`). For a billing restriction that headline is the wrong first line.
- **Why deferred, not fixed:** low severity with a real mitigation — `toolResultContent` appends each error's message + hint directly under the headline in the same `content` stream, so a 402 carries "Subscription required…" plus the billing hint immediately below, and `structuredContent.errors[]` has the same detail for machine consumers. Only a host that shows the headline alone misreads it. The clean fix is a design decision, not a release-branch patch: the `ToolError` model cannot currently distinguish a paywall from an unreachable API by `class`+`location` (the 402 arm sets no location), so a billing-specific headline needs a new discriminator (e.g. optional `kind?: "paywall"` set in the 402 arm) threaded through all five summary mappings across four files.
- **Recommendation:** if pursued, add the discriminator in `classifyApiResponseError`'s 402 arm and special-case it in the summary wrapper functions (before the class map), with one shared billing headline; per-tool projection tests assert a 402 yields the billing headline instead of the connectivity one. The settled `class: "config"` contract stays untouched. Decide whether the confusion risk on headline-only hosts justifies widening the `ToolError` model — otherwise close the thread as accepted behavior.
